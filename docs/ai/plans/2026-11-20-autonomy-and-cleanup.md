**Goal:** eliminate routine approval prompts across Copilot and Kiro (asking ONLY on sensitive/destructive actions while blocking hard stops), align the `work` profile and `sync.mjs`, and provide a reusable cleanup tool that clears old debug logs, transcripts, VSIX caches and scratch files.
**Done when:**
- `_ai/hooks/guard.mjs` classifies tool calls into 4 outcomes:
  - **deny** (exit `2` + `permissionDecision: "deny"`): writing SQL via DB client, hard stops (`push --force`/`-f`, `down -v`, `docker volume rm/prune`, `docker system prune`, prod/staging compose, `release.sh`/`rollback.sh`, `ssh`/`scp`/`sftp`, and MCP hard stops Hostinger `execute`/`multi-execute`/`execute_site_tool` + Atlassian `executeDestructive`), `.env`-style files, and `personal/`.
  - **ask** (exit `0` + `hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "ask", permissionDecisionReason }`):
    - shell commands whose pipe stages are not pure `SEARCH`/`echo` and invoke: file deletes (`rm`, `del`, `erase`, `rmdir`, `rd`, `ri`, `Remove-Item`, `clean.mjs --apply`, `[IO.File]::Delete`, `[IO.Directory]::Delete`, `rmSync`, `rmdirSync`, `unlinkSync`, `fs.rm`, `shutil.rmtree`, `os.remove`, `os.unlink`, `.unlink(`), Git writes (any `git` invocation including `git -C <dir>` or `& git` whose subcommand is not read-only `status|log|diff|show|ls-files|blame|rev-parse|grep|remote -v|branch --show-current|--version|merge-base|stash list|config --get`), external CLI/network/publish commands (`az`, `gh`, `curl`, `wget`, `Invoke-RestMethod`, `Invoke-WebRequest`, `irm`, `iwr`, `npm publish`, `pnpm publish`, `docker push`, `kubectl`, `helm`, `terraform`), or business-data runner scripts (`run_notebook.py`, `seed_lake.py`, `copy-from-dev.ps1`, `dev.ps1 Notebook`, `dev.ps1 Lake`);
    - edits (`replace_string_in_file`, `multi_replace_string_in_file`, `create_file`, `insert_edit_into_file`, `edit_notebook_file`, `Edit`, `Write`, `NotebookEdit`, `write`, `fs_write`, `str_replace`) targeting paths **outside** the workspace root `ROOT`;
    - mutating MCP tools (`mcp_` / `mcp__` tools matching `create|update|delete|add|edit|transition|comment|send|post|register|rename|restore|set_|log_|apply_changes`, plus `mssql_dab` when `operation === "apply_changes"`).
  - **allow** (exit `0` + `hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "allow" }` ONLY when `--allow` is passed on `run-guard.mjs` AND `canAutoAllow(toolName, args, cwd, root)` is true: read/search/subagent/diagnostics/memory/read-only-MCP tools, in-workspace edits, and `run_in_terminal` commands that passed `check` and `checkAsk`; unknown tools return silent exit `0` so VS Code decides).
  - **silent pass** (exit `0`, empty stdout): default for Claude Code, Kiro, and unknown tools.

## Context
- **Why 100+ prompts happened (proven from VS Code 1.147.0 `workbench.desktop.main.js` @15794940 & Copilot `extension.js`):**
  1. `copilot_readFile` / `list_dir` outside the workspace folder always attach `confirmationMessages: { title: "Allow reading external files?" }`.
  2. File edits (`replace_string_in_file`, `create_file`) attach `"Allow edits?"` unless auto-approved.
  3. Terminal commands containing file writes outside workspace or flagged patterns trigger `terminal` confirmation.
  4. In `workbench.desktop.main.js` (`resolveAutoConfirmFromHook` @15794940): when a `PreToolUse` hook returns `permissionDecision: "allow"`, VS Code logs `Tool <id> auto-approved by preToolUse hook` and sets `autoConfirmed` — skipping confirmation dialogs! When it returns `permissionDecision: "ask"`, VS Code sets `allowAutoConfirm: false` and forces a confirmation prompt with the hook's reason!
- **Kiro parity (proven from `kiro.kiro-agent/dist/extension.js` @2792157, @2793589, @11983448, @15946835):**
  1. In `Q6e` (@2793589), omitting `matcher` (`e.matcher.source === undefined`) matches **every** `PreToolUse` tool call (`shell`, `read`, `write`, `grep`, `glob`, `subagent`, `mcp`).
  2. Exit `2` blocks (`p.blocked`); exit `0` + `hookSpecificOutput.permissionDecision: "ask"` sets `p.ask = true` and prompts the user even when Kiro's `permissions.yaml` has `capability: all, effect: allow` (`Autopilot`).
  3. Kiro's workspace permissions file `C:\Users\GOCIURDU\.kiro\workspace-roots\1d32d89549232862\permissions.yaml` already has `# >>> generated by node _ai/sync.mjs` markers from an earlier local experiment; keeping that block synced by `sync.mjs` guarantees Kiro never prompts on reads, subagents, workspace edits or tests.
- **`debug-logs` value (proven from `chronicle/SKILL.md` & disk scan):** `debug-logs` (4.3 MB, 61 folders) are raw Copilot turn logs only used if `/chronicle reindex` rebuilds the session index (which isn't even enabled: `session-store` DB is absent); active session `05272e13...` must be skipped, older ones are safe to delete. Bigger wins: Kiro `CachedExtensionVSIXs` (412 MB) + VS Code `CachedExtensionVSIXs` (153.7 MB) = **565.7 MB** of already-installed `.vsix` downloads, plus old `.kiro/sessions` (>7d: 298 files), old `Code/logs` / `Kiro/logs`, `.tmp/test_mlflow_mcp.py`, and superseded `docs/ai/reports/2026-11-16-review-setup*.html` (staging/committing deleted `2026-11-16` plans stays with the user per Git rules). ## Risks
| Risk | Effect | Mitigation / rollback |
|---|---|---|
| `permissionDecision: "allow"` auto-approves a destructive command | Unintended delete, Git write or external call | `check()` (hard deny) runs first, `checkAsk()` (deletes, Git writes, `az`/`gh`/`curl`/`irm`/`iwr`, mutating MCP tools, inline `rmSync`/`unlinkSync`) runs second and returns `"ask"`, and `"allow"` is emitted ONLY when both return `null` |
| Inline `node -e` / `python -c` deletes files bypassing `rm`/`del` regex | Unprompted file delete | `checkAsk()` also matches `rmSync`, `rmdirSync`, `unlinkSync`, `fs.promises.rm`, `shutil.rmtree`, `os.remove`, `os.unlink`, `.unlink(` in shell commands |
| Cleanup deletes an open chat session or active project report | Lost active conversation or project doc | `_ai/clean.mjs` never touches files modified within `--days` (default 7, except `CachedExtensionVSIXs` installers and `.tmp/*`), never touches `VSCODE_TARGET_SESSION_LOG`, and never touches `<project>/docs/ai/` |
