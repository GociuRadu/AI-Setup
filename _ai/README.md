# AI core (`.claude` + `_ai`)

Claude Code setup for the `projects` workspace. User guide: [HOW-TO-USE.md](../HOW-TO-USE.md).

## Layout

| Path | Purpose |
|---|---|
| `CLAUDE.md` (root) | Core entrypoint; imports the global rules |
| `.claude/instructions/` | `global`, `python`, `sql` rules (edit only here) |
| `.claude/rules/python.md`, `sql.md` | Path-scoped loaders for the language rules |
| `.claude/settings.json` | Permissions |
| `.claude/agents/` | Subagents `scout`, `worker`, `tester`, `reviewer` |
| `.claude/skills/` | `analyze`, `review`, `bug`, `data`, `confluence`, `ponytail`, `lead` |
| `AGENTS.md` (root) | Entrypoint for non-Claude agents; links the same rules and skills |
| `_ai/templates/basic/`, `data-eng/` | Project skeletons (entrypoints `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md` + `docs/ai/`; data-eng adds the project1 source/test layout under `code/`). Placeholders `{{PROJECT}}`, `{{DATE}}`, `{{CODE}}`, `{{CODEDIR}}`, `{{ROOT}}`, `{{DB_ACCESS}}` |
| `_ai/scripts/new-project.mjs` | Creates a project from a template (`--setup personal|work`); never overwrites |
| `_ai/SOURCES.md` | External origins and licenses |
| `_ai/scripts/build-work.mjs`, `_ai/work-overrides.json` | Generator for the work (Copilot) copy of skills, helper agents and language rules |
| `work/` | Copy of the Copilot work setup (strict permissions), refreshed from the Obsidian vault `Me/Code/Setup/work`; `dot-*` names restored to `.*`; `personal/` excluded |

Project module: `<project>/CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md` (what to read, same content), `docs/ai/` (`project.md`, `context.md`, `memory.md`, `reports/`), `code/` (Git checkout).

## How the pieces connect

| Piece | Loaded | Depends on |
|---|---|---|
| Global rules | every session (imported by root `CLAUDE.md`) | links ponytail for code style |
| Python/SQL rules | when a `.py`/`.sql` file is in scope (`.claude/rules/`) | global rules |
| `lead` | plan/design, risky path (loads, migrations, auth, shared config/schema), wide work (5+ files) | all four agents; global Agents section |
| `review` | `/review` or a review request | `project.md` Review focus; its checklist is reused by `reviewer` |
| `bug` | a failure report | `memory.md` Bugs, `tester` |
| `data` | data model/pipeline/notebook work | its own `model/`, `pipeline/`, `spark/` files; `project.md` Conventions |
| `analyze`, `confluence`, `ponytail` | on request or by description | global rules |
| Agents | started by `lead` or the main session | read `project.md` (Commands, Review focus) |

Rule precedence: hard stops > global rules > project `project.md`/repo rules (only stricter) > skill defaults.

## Maintenance

- Add a skill: `.claude/skills/<name>/SKILL.md`. Record external sources in `SOURCES.md`.
- Change a model: `model:` in the agent frontmatter; `lead` follows the session model (`/model`).
- Work setup: skills, helper agents and `python`/`sql` instructions are generated by `node _ai/scripts/build-work.mjs` from `.claude/` plus the work-only differences in `_ai/work-overrides.json`, into `work/_ai/.github` and the vault (`dot-github`, CRLF); it also mirrors the core (`.claude`, `_ai`, root `CLAUDE.md`/`AGENTS.md`/guides) to the vault root, same layout as git (dot-* names, CRLF, never deletes). The vault's `work/` is only compared, because work-owned files arrive there from the work workspace. `--check` reports drift in all three (exit 1). A deliberate work-only edit: change the file in `work/`, then `--derive`. A build error "anchor found 0 times" means a core edit touched a work override: fix that work file by hand, then `--derive`. Work-owned, never generated: `lead.agent.md`, `global.instructions.md`, `copilot-instructions.md`, hooks, docs.
- After any change: run `node _ai/scripts/build-work.mjs`, start a new Claude Code session in `projects`, then commit and push. The setup is versioned in `GociuRadu/AI-Setup` (`projects` is the repo root; the whitelist `.gitignore` keeps project folders and `personal/` out).
